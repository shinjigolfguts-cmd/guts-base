# お気に入り一括削除の失敗時表示

## 確認した問題

基準は GitHub main `7144e869fe80a478d5fc6875cd0fb71df54dfcb0`。
既存公開照合レポートの `app.js` SHA-256 と保存済みコードが一致することを確認した。
「データとプライバシー」の一括削除は、ブラウザー保存領域の `removeItem` が例外になっても、画面内のお気に入りを空にし「お気に入りを削除しました」と通知していた。
保存領域に元の値が残るため、実際には永続保存を削除できていない。

これは保存領域の例外を模した無通信VMでの再現であり、利用者の実ブラウザーで障害が発生したという報告ではない。利用者の保存データには触れていない。

## 最小修正

- 永続保存の削除を先に行い、成功した場合だけ表示状態の解除・完了通知・ダイアログ終了を行う。
- 保存領域へのアクセスまたは削除が失敗した場合、お気に入り・表示条件・ダイアログを保つ。
- 失敗案内はダイアログ内の `role="status"` に表示する。ダイアログの背後になる通知だけに依存しない。
- 自動再試行は追加しない。利用者が後で再び押した場合は、その操作について一度だけ試行する。
- 正常時の文言・保存キー・他の保存値・無関係クリック・個別保存/削除は変更しない。

## 検証

既存 favorites テスト9件に、次の6件を追加した。

1. 通常一覧/お気に入り一覧からの正常一括削除と他キーの保持。
2. `removeItem` 例外で保存状態・開いたダイアログを保持し、成功を通知しない。
3. `localStorage` プロパティ自体へのアクセス例外でも同様に停止する。
4. 失敗後に利用者が再度操作し、保存領域が利用可能なら正常に削除する。自動再試行はない。
5. 空の状態からの操作と、無関係なクリックの無処理。
6. 失敗案内がプライバシーダイアログ内の穏やかな読み上げ領域にあること。

LOCAL: Node 75件、Python 41件、合計116件とJavaScript構文検査が成功。
元の `app.js` を用いた負例では、追加テストのうち失敗保持・保存領域アクセス例外・失敗後再操作・案内領域の4件が失敗し、見逃していた経路を検出した。
集約カタログ/全画像検査は通常のPR CIで確認する（LOCAL診断用ディレクトリには画像本体を複製していない）。

本変更は `app.js`、既存favoritesテスト、この記録のみ。カタログ・価格・順位・計測・保存キー・権限・実行スケジュールを変更しない。PR CI・公開・実ブラウザーの結果は各実行後に別途記録する。以前のスマートフォン確認はこの変更の確認済み証拠に流用しない。
